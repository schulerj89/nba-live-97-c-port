## Rating focus and keyboard regression boundary

The fifth Help page belongs to **group selection**, not a separate single-rating child. `FUN_80040FCC` reads byte `+9` of the selected descriptor in the screen-`0x22` context (`0x800BF8E0`, pointer table at `+0x88`):

| Retail descriptor row | Context | Help page |
|---|---|---|
| `0x1E/0x1F` | First/Last Name selected | 1 |
| `0x1E/0x1F`, temporarily changed by `FUN_8004C488` | Active inline name | 2 |
| `0x00..0x0D` | Attributes | 3 |
| `0x0E..0x1D` | Individual detailed rating | 4 |
| `0x20..0x23` | Four-rating group summary | 5 |

Cross calls `FUN_8004B400`: it remembers the individual row, dims the four detail rows, pulses the group summary, and plays sound 6. `FUN_8004B4F8` restores the remembered row. Group Up/Down callbacks are null. Left/Right reach `FUN_8004B600/688` through `FUN_8004B710`: mixed values clamp individually, but an entire group already at the boundary wraps together (50 to 99, or 99 to 50). This retail quirk is intentional. Tests cover all 16 remembered rows, all four groups, mixed limits, Help routing, cancellation, and save/reopen; the focus flag is transient and does not change the save format.

The name Help art identifies Circle as backspace and Square as delete; callback token `0x40` is not a raw R1 pad bit. The host uses C/Cross, V/Circle, D/Square, F/Triangle, Enter/Start, and Right Shift/Select. Escape is a Select convenience in Create Player and is routed to the editor before the global app-exit handler. `win32_keyboard_delivery` checks Shift scan-code normalization (`0x36` right, `0x2A` left), key-up/down, and name callback tokens. Real physical Right Shift delivery is a separate live check: the desktop automation helper currently emits generic Shift with scan code zero. `CREATE-KEY` logs raw key, scan code, normalized key, callback token, and editor/name/group state to make that distinction observable.

Live native walkthrough on 2026-08-29 additionally exercised Cross entry, uppercase seeds in both name fields, Cross/add, Square/delete, Circle/backspace, Start/name accept, Escape/name rollback, all intervening rows through Field Goals, Help page 4, Cross/group focus, Help page 5, group 50/99 wrap in both directions, group Down no-op, remembered Field Goals return, draft cancellation, and manager return to Rosters. ## Edit acceptance and value-boundary regressions

Start on an unchanged Edit is a successful acceptance: it returns to the manager without rewriting the file or advancing its generation. `CreatedPlayerStore::acceptEditor` owns candidate validation, optional durable writing, and publication together. `Invalid`, `Unchanged`, and `Written` are distinct outcomes; an actual I/O exception retains the live draft/catalogue. Tests cover unchanged and change-then-revert acceptance, missing names, forced temporary-file failure, retry, and reload.

The generic retail value callbacks `0x8003AC10/0x8003AC6C` call `0x8003A128` with opposite-endpoint replacement, not clamping. All 13 non-name attribute controls now cycle both ways over the port's currently supported domains. Tests sweep every value in both directions in New and reopened Edit, including a 347-entry College fixture and zero/one-entry tables. The capture verifier additionally invokes the actual Edit picker/keyboard handlers against an isolated save: unchanged Start exits, College and jersey wrap both ways, and reverted Start leaves catalogue/generation unchanged. The current loaded College list has 191 choices, built from the roster database.

This boundary fix is not a claim that every domain matches retail yet. Static screen-`0x22` descriptors expose separate range/content gaps: 101 jersey entries (including the retail `100 -> 0xFF` special-number encoding), 32 height entries, 160 weight entries, 347 College entries, 21 Years Pro entries, 12 Skin Tone entries, and 16 Shooting Range entries. Range changes, the complete authored College table, and their dependent model/save mappings remain a separate recovery boundary; this patch preserves the existing domains and renderer. Do not count wrap tests as proof of those missing retail entries.
