# Original net and rim pass

`game_net.c` owns GAME `4B1A4`, `4B6C4`, `4BA84`, `4C144`, their named matrix/projection leaves, and the actual ZNET `A4744 -> A464C -> AA168` decoder path. `GameNet` joins those C owners to an existing checked original-address memory context and `GameNetGeometry`. Production has no instruction interpreter, resource substitute, successful loader stub or assumed camera. This is one pass required by `49018`, not a claim that the native application has reached a natural match frame.

## Resource and source order

The original `52C20` owner writes one to `B72DC` at `52C48`. Its resource path calls `29BFC` at `530D0` with the actual filename at `26404`, then publishes the returned ZNET pointer to `103F44` at `530DC`. Those loader/heap/arrival effects are prerequisites, not implemented here. The native entry consumes their retained results and never invents a successful loader return.

When `B72DC` is nonzero, `4B1A4` first runs `4B6C4`. This adds the live resource base to each of its 30 offsets **in place**, then copies those 30 references into `102938`. A repeated initialization adds the base again; the original has no already-relocated guard. It initializes both packet banks for both baskets: 15 groups of three differently shaded rim line packets, two flat rim quads, and 100 net line packets. It derives 15 world rim vertices from the actual `B731C` table, mirrored about X with offset `AC0` and height `280`. It reads the existing `B7A00`/`B7A04` frame counters, decodes each selected frame to `FB998`/`FBFD8`, and publishes those addresses at `1076EC`/`108A10`. No counter reset is invented.

The standalone initialization entry does not write the outer flag or draw count. The outer owner then writes `103FA8=100` and clears `B72DC`. It runs **all drawing before animation/deformation updates**, preserving the original one-pass latency. Pausing is read through the actual `FC660` pointer. An active frame counter increments with wrapped 32-bit addition followed by signed remainder modulo30. Negative/malformed counters are not normalized into valid table indices. Rollover writes first-basket angle `1076E6=800` but second-basket angle `108A0A=0`. A paused zero counter still decodes frame zero. The independent `B7A08`/`B7A0C` deformation timers alter 200 vertex Y values even while paused; only decrement is gated by pause. Rim restoration uses the original reverse store order.

`4BA84` reloads the real camera at `F9FD8`, reads the live bank at `1EDE8`, projects the two rim quads and fifteen triple-line groups, and preserves every repeated visibility/global/table read. `55F60` uses RTPT then RTPS, writes all four endpoints, then AVSZ4. The original FLAG/IR0 temporary outputs feed dead private stack storage; they are not used as invented culling conditions. The actual mask and suppression reads control linking. Each link invokes existing `56914`, retaining its low24-bit packet and ordering-table store order.

After rim drawing, nonzero `DCF10` skips the net lines. Otherwise each visible net runs `4C144`. It masks and rewrites the three real `FA638` Euler angles, composes the source matrices, and scales **only the first matrix row** by16/10 using signed arithmetic. This source quirk is not changed into uniform scaling. It transforms the actual `FAB98` position, composes the per-net angle matrix at `1076C4 + side*1324`, and adds signed `FA630` translation. The render loop reloads `103FA8` after every pair of lines. With its source value100 it draws96 of the100 initialized line packets per bank; the final four are unused. It does not replace the signed live loop bound with a fixed native count.

## Actual ZNET codec

The private original `ZDOMZNET.BIN` resource is19,348 bytes (19,336 logical bytes plus trailer), SHA256 `af4a0c06af781b0d30da1f0c4082f8fc108f1b0b24407caab558da849740bf95`. All30 frame offsets select `10 FB 00 06 40` headers and the `AA168` command decoder. Each original frame decodes to1,600 bytes, or200 eight-byte vectors. No proprietary resource bytes are included in public tests or source.

`A464C` reads the three-byte declaration before checking the signature, then checks byte+1 for `FB` or `32`. It uses byte0 and the **live original jump table at288B4**, not an inferred selector map. The owned target `A46CC` calls `AA168`; invalid signature, selector range, or actual default target retains the original zero-return behavior. Selected `A4864`, `A62E8`, `A5970`, or another unsupported dispatch target returns explicit `NET_CODEC_REQUIRED` at the reached call/dispatch boundary. No alternate decoder is silently substituted.

`AA168` supports its optional header field and all four literal/backreference command forms. It returns the declared length but does not use that length to bound writes: only the stream's termination command stops it. This unchecked original behavior is retained behind native memory/operation guards. Overlapping backreferences read newly written bytes in original order. Opaque literal and backreference bytes retain per-byte unknownness without clearing backing bytes. Control bytes and address arithmetic inputs must be known. Unknown declared-length bytes can yield an unknown returned length because the source frame caller discards that return. The owner does not append a terminator or zero-fill a destination.

## Retained memory and math contract

The C entry uses `Nba97PlayerFrameContext` with its existing exact original address, width, reference and per-byte knowledge contract. The child callback is unused. Each reached span, including write-only bytes, must have canonical metadata. Unknown unused padding is not forced known. Original wholeword reads feeding signed16 GTE fields validate all reached metadata while requiring only the consumed bytes to be known. Pointer stores remain explicit and retain original source encodings; byte copies preserve overlap and knowledge. Referenced code and private ABI stack must not alias visible allocations. No original SP or private stack padding value is manufactured as an externally visible address.

Every refusal retains earlier CPU stores and geometry changes. `Nba97GameNetProgress` reports operations, successful reads/stores/math calls, decodes, initializations, links and the stopped original PC/address. The operation budget is a native safety guard, not a recovered source count or a resumable source PC. Missing resources, misalignment, invalid metadata, unknown consumed bytes or an unsupported codec never become success. The existing aligned low24 packet-link domain remains bounded; other MIPS LWL/SWL alignments are explicitly unsupported rather than mislabeled as a source LW trap.

`GameNet` borrows a checked memory context, such as `GamePlayerFrame::bindContext` output. Only that context's memory callback and user are forwarded; its old math/child callbacks are not used. Its backing bytes, knowledge, cells, address mappings and callback user must remain valid throughout the synchronous call. Copies of this adapter do not clone memory. For atomic publication, clone/rebind the complete memory owner and copy geometry before execution, then publish after success.

`GameNetGeometry.player` imports/exports the existing `GamePlayerProjectionGeometry`: rotation, translation, vertices, IR/MAC, flags, screen/depth FIFOs and order depth remain shared with earlier player/court passes. Its independent `average_scale4` is the actual retained ZSF4; it must not be inferred from ZSF3 or a default camera. Named MVMVA, RTPT, RTPS and AVSZ4 operations use the existing native integer arithmetic. Export geometry after **success or refusal**, since earlier source math effects remain live. The implementation does not reset unrelated retained geometry words.

A composition therefore borrows the existing checked memory context, assigns `net.geometry.player = player.geometry` and the actual ZSF4, invokes `net.frame`, then assigns `player.geometry = net.geometry.player` regardless of return status. The entry has no texture/VRAM upload requirement: it builds colored line and flat-quad primitives from the real decoded net and rim geometry. Packet rendering still needs the existing live ordering-table and GPU state, including partial packet-word knowledge.
