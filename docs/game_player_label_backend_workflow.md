# Native player-label composition

`runGamePlayerLabels` connects original35A44 to the recovered30758 group reset,
30D18 object/packet creation, and99960 reset wrapper. C++ retains the memory and
binds its proven source addresses; the portable C owners perform the original
behavior. This is a callable composition, not a visible in-match label layer.

All bindings describe views in the same `GameRenderMemory` owner, with known
original alignment and explicit original source addresses. The bridge rejects
overlapping source ranges or an address/alignment mismatch. Different source
bindings may alias native storage. The returned object's original identity is
retained for35A44's immediate object/object+4 resets rather than reverse-mapping
an ambiguous native pointer. No source address is derived from a host pointer.

35A44 creates its temporary label text; the text owner consumes that live span
without a fabricated original stack address. Its returned object is a view of
the real retained64-byte object. Both packet-bank resets inside creation and
both repeated resets in35A24 remain. The C567C reference is not interpreted as
an empty-list sentinel by this bridge. Text/glyph/pool allocation, original
exhausted-slot behavior, and packet writes remain in the recovered C owner.

The legacy35A44 interface has no knownness channel, so this bridge supports
fully known player/string/style/object buffers. It rechecks live player and
position-string buffers after every completed callback, including replacement
views and newly unknown data, before35A44 can read them. It refreshes the style
from the current B2048 word after each completed callback and refuses an odd
style address before legacy halfword stores. Text resources keep
their per-byte knownness throughout their own C operations. This is an explicit
native supported-domain restriction; it does not add checks to the original.

The SDK diagnostic/DMA callback is required. Null or refused operations stop
without fabricated success. Completed resource writes, object links, and
callbacks remain on failure. To publish atomically, the caller must clone the
memory, rebind all borrowed input views and stage external callback state as
well; the bridge itself operates in place and does not promise rollback.

Private Debug and Release builds use `/W4 /WX` and pass71 checks: ten real
object creations and forty required SDK fixture calls; source packet positions
and list resets; source failure prefixes; missing SDK, malformed bindings and
unknown legacy data; callback-induced unknown next-player data and odd style;
and complete
isolation of a cloned memory generation. The SDK test callback is an explicit
fixture, not DMA hardware proof. Native font loading, initial source-address
provenance, SDK/DMA completion and frame rendering remain required separately.

Independent review compared64 compositions per build against original35A44,
35A24 and the full recovered text CPU chain, including3480 SDK callbacks,
live-style changes, repeated resets and failure prefixes. Each build matched
49 complete cases and15 explicit refusals. Only SDK/diagnostic and libc
format/copy boundaries were supplied; no text-object success stub was used.
The private `label_backend_proof` receipts bind the tested DLL and source
hashes. The final integrated Debug and RelWithDebInfo builds pass all98 CTests.
