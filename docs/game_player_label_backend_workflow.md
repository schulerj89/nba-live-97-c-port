# Native player-label composition

`runGamePlayerLabels` connects original35A44 to the recovered30758 group reset,
30D18 object/packet creation, and99960 reset wrapper. C++ retains the memory and
binds its proven source addresses; the portable C owners perform the original
behavior. This is a callable composition, not a visible in-match label layer.

All bindings describe views in the same `GameRenderMemory` owner, with known
original alignment and explicit original source addresses. The bridge rejects
overlapping source ranges or an address/alignment mismatch. Different source
bindings may alias native storage. The returned object's original identity is
retained for35A44's immediate object/object+4 resets rather than reverse-mapping
an ambiguous native pointer. No source address is derived from a host pointer.

35A44 creates its temporary label text; the text owner consumes that live span
without a fabricated original stack address. Its returned object keeps the
actual source identity, even when different object fields occupy separate native
allocations. Both packet-bank resets inside creation and
both repeated resets in35A44 remain. The C567C reference is not interpreted as
an empty-list sentinel by this bridge. Text/glyph/pool allocation, original
exhausted-slot behavior, and packet writes remain in the recovered C owner.

The bridge uses `nba97_game_player_labels_checked`. The C owner requests only
each reached byte read or halfword store; its resolver returns retained data,
per-byte knownness, and original alignment. Reads require known bytes. Stores
accept unknown bytes, validate every reached metadata byte as canonical0/1,
and establish knownness when the original store occurs. Invalid metadata is
not repaired. Unknown unread padding and unselected strings remain untouched.
The original entry remains compatible with fully known, source-aligned buffers.

B2048 is read at35A60,35B5C and35BBC, before the stores at35A74,35B70 and
35BC4 to style+2A,+26 and+2A. A callback-induced unknown next name or odd style therefore does not
skip the current label's remaining99960 resets. Source ranges are checked only
for the reached operation; an unused style tail or object padding need not be
mapped. The checked CREATE return carries a one-byte native identity. OBJECT
accesses resolve its saved original address; checked RESET events retain that
identity and supply `object_offset`0/4 instead of constructing a host pointer
into another allocation. The old entry still advances its flat buffer pointer
for the second reset and supplies offset0. `labels.style` is an informational
one-byte identity when the style base is mapped, or empty when only its reached
fields are mapped; it is not a replacement full-style resource.

The text owner also preserves opaque font tags through31344LW/3134CSW.
2EA80 can copy unknown incoming low24 stack bits into a glyph descriptor. They
are copied with their knownness, including through the second packet-bank
copy, until56914 replaces the address bits. No invented09FFFFFF terminator or
zero-fill is needed. Unknown bits refuse if the destination has no knownness
channel. This corrects a port validation defect; the original writes and their
ordering are unchanged.

The SDK diagnostic/DMA callback is required. Null or refused operations stop
without fabricated success. Completed resource writes, object links, and
callbacks remain on failure. To publish atomically, the caller must clone the
memory, rebind all borrowed input views and stage external callback state as
well; the bridge itself operates in place and does not promise rollback.

text-owner checks: ten real

Independent review compared64 compositions per build against original35A44,
35A24 and the full recovered text CPU chain, including3480 SDK callbacks,
live-style changes, repeated resets and failure prefixes. Each build matched
49 complete cases and15 explicit refusals. Only SDK/diagnostic and libc
format/copy boundaries were supplied; no text-object success stub was used.
The earlier `label_backend_proof` receipts describe the previous restricted
bridge. New `label_partial_known` receipts bind the replacement DLL/source
hashes without overwriting those earlier receipts. They rerun64 composed label
cases,240 old-entry label cases, and928 full text-owner cases per configuration.

The new composed resource proof also runs actual2E200 followed by ZKERN12,
ZKERN10,ZKERN22,ZOVLFONT,ZBLACK12 and35A44. Five fonts produce482 glyphs;
35A44 selects the second font, ZKERN10. Eight complete cases and nine explicit
refusal cases compare ordered callbacks and all non-stack RAM against original
CPU instructions. Initial pool bytes retain arbitrary payloads and unknownness;
the five fonts establish only their real fields. ZOVLFONT's logo path really
writes style colors0/4, while unused spacing/kerning slots remain unknown.
These are explicit source-address/allocator/load/release/SDK fixtures, not a
proof of9027C/90698 heap behavior, GPU hardware, or natural startup. Per-byte
knowledge is checked at producer/consumer boundaries; the complete RAM byte
comparison does not claim an independent bit-taint CPU model.
