# GAMEONLY match initializer recovery

`src/recovered/game_match_initialize.c` owns the complete GAMEONLY routine at
`0x8002DB90..0x8002DC37`: 168 bytes and 42 instructions. A fresh read-only
Ghidra listing identifies recovered match-session `0x8002D8D4` as its caller at
`0x8002DA7C`. The routine digest recorded by that evidence is
`c1569d2ae6b58be97cd7511f5dd2bee7be70684d9e1fc9ba9abd3ad9f83ce6f3`.

The owner preserves the source sequence. It reads the two live team words at
`0x80021D74` and `0x80021D78` before changing `sp`, saves `ra` at entry
`sp-8`, and copies the two raw words and their per-byte knownness to
`0x80022084` and `0x80022ADC`. It then calls zero-fill entry `0x800A3A74` with
`a0=0x800FDB4C` and the delay-slot value `a1=0xE7C`, calls ten subsystem
boundaries, clears word `0x80020C18`, calls the final subsystem, reloads `ra`
through the live `sp`, and restores that live stack pointer by `0x18`.

All 32 GPRs cross child boundaries as explicit 32-bit guest register values
with per-byte knownness. Each callback observes `ra=call_pc+8` and the executed
delay slot. In particular, the `0x80038A18` callback receives known
`a0=0xFFFFFFFF`; its mutations then flow across the flag store into the final
`0x800763F4` call. The final child's `v0` and other live registers are returned
unchanged except for the source epilogue's `ra` load and `sp` addition.

`src/game_match_initialize_adapter.cpp` is the narrow production composition
for the immediately composable recovered callee. It dispatches `0x800A3A74` into
`nba97_game_memory_zero`, preserves partial incoming `v0` knownness because the
zero owner never writes it, and publishes the child's live `a0`, `a1`, and
known-zero `a2`. For this fixed aligned large clear, the zero-core listing also
proves and the adapter publishes its live scratch outputs `at=0`, `t0=4`,
`t1=0`, and `t2=0` after the first SWR. A failure at that first store retains
incoming `t0`/`t1` while still publishing the earlier `at=0`, `a2=0`, and
`t2=0` instructions. The remaining eleven original callees stay behind the typed
initializer callback. A helper maps the register state proved by the natural
match-session event; registers absent from that older caller interface remain
explicitly unknown until overwritten by this routine or a child.

The direct asset-free test generates retained RAM and stack bytes at runtime.
It checks all twelve call PCs and targets, delay slots, register forwarding,
the seven parent memory accesses and their order, partial snapshot knownness,
every callback refusal, every operation-budget prefix, malformed callback
state, missing/overlapping mappings, alignment, unknown stack/return state,
live saved-`ra` mutation, final `v0`, and the real zero owner's exact clear.
The separate integration test enters through recovered match-session at its
natural `0x8002DA7C` call, composes the same production adapter, and proves both
completion and a bounded zero-child failure prefix with generated bytes only.

This CPU orchestration routine has no direct visual effect. It creates no
framebuffer, GPU packet, UI, or advancing match state. Downstream scene-load
and match-loop children remain unresolved, so this recovery must never be
reported as gameplay.

`src/game_match_initialize_capture.cpp` now dispatches the same production
adapter at the natural match-session call in the self-driving native capture.
The existing input handlers drive Game Setup, Team Select and User Setup.
The initializer clears 3,708 runtime-generated sentinel bytes through the
recovered zero owner, publishes the two team snapshots and clears the final
flag before its last callback. Eleven explicitly synthetic child responses
exercise the full call order without fabricating simulation or rendering.
The native receipt records all seven parent memory accesses and eleven child
PC/target pairs, 19 parent operations, 928 zero-owner stores, final `v0` and
restored `ra`/`sp`. Immediate before/after captures remain pixel-identical;
`match_initialize_verified.json` records their SHA-256 values and input frame
indices in the ignored capture directory.

Several callees have existing projected implementations but still need
retained-state/resource adapters before this source call can use them:
`0x80063D58` (bounded match setup), `0x800640D8` (mocap loading),
`0x80065DB0` (period coordinator), and `0x80038A18` (head-cache services).
`0x8002AB30` is represented by a native color helper and `0x800659F0` by partial
projected effects. `0x80029114`, `0x8007FD40`, `0x800294F8`, `0x80031E00` and
`0x800763F4` remain unresolved. Typed callbacks preserve these dependencies;
this commit translates none of their bodies.
