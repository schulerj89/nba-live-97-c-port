# Camera overlay packet preparation recovery

`game_camera_overlay_packets.c` owns GAMEONLY `80075D40..80076273`: the CPU-side camera overlay selection, rectangle writes, packet-link dispatch, live mask loop, optional projected-quad setup, ten-argument projection boundary, and source stack epilogue. It uses mapped 32-bit guest addresses, byte knownness, all 32 GPRs, HI/LO, callback-visible delay slots, and a mutable stack pointer. The implementation follows human-readable source basic blocks and does not decode instructions at runtime.

The recovered entry retains the source gates. States below three and state seven bypass selection. The selected-player route requires `BC1F0`, the signed owner table result, and a zero `F9FFE`. State five or later may construct the secondary rectangle. Both rectangle coordinates use signed `< 56`, so negative coordinates remain accepted. Each rectangle repeats the live coordinate, table, and bank reads and writes eight halfwords in source order before its link call. The two fixed packets at `FA25C` and `FA284` are linked after that route.

When `F9FFE` is nonzero and `FA038` is zero, the source initializes the one-bit cursor and scans the live mask through a nominal thirteen iterations. Each callback may replace S0, S1, S2, S3, SP, HI, LO, memory, and every other register. The loop therefore uses the returned machine and relies on the operation budget to bound source-valid runaway mutations. Its final `FA054` link is unconditional.

Bit `0x80` selects the projected quad. The owner clears four Y halfwords, writes the wrapped `SLL 3` X/Z coordinates around ±128 in the original order, dispatches the typed rotation and translation children, and prepares the six stack arguments for `55FE4`. The last output pointer store is the JAL delay slot. A final live-bank link inserts the projected packet at the end of the ordering table.

The C++ child mux reuses `nba97_game_court_link` for the aligned `56914` domain. The fresh five-instruction evidence proves the machine bridge: the successful known low-24 table read updates T0 while retaining its low byte; `SLL T1,A1,8` then updates T1 with wrapping and byte knownness before any packet-write failure. Every other GPR and HI/LO stays unchanged. The existing owner supplies the packet-store then table-store memory order and alias behavior. Unknown low-24 reads, unknown call addresses, malformed call metadata, and unaligned addresses refuse explicitly because the shared owner exposes only its aligned, known-low24 domain. The GTE children remain typed full-machine callbacks.

The match-frame adapter binds the actual `49018` callback at `490C8`. Since that parent callback contains no machine or retained-memory payload, the adapter requires explicit independent inputs and validates a fully known RA of `800490D0`. The parent does not consume this child's return value, so successful dispatch canonicalizes a supplied return container to unknown instead of retaining stale caller data. All other match-frame callbacks are forwarded to the configured owner.

Validation is asset-free. The focused suite covers signed state and coordinate edges, both rectangles, wrapping values, bank offsets, all ten call sites, loop masks and live mutations, bounded runaway behavior, the projected-quad stack arguments, callback refusal and malformed machines, unknown data and pointers, alignment, mapped-memory validation, every operation cutoff, and wrapped SP. Integration tests execute the real `56914` owner, its exact T0/T1 effects and aliases, and the natural `49018 -> 75D40` boundary.

This routine has no direct visual effect until the prepared packets are consumed by the actual renderer. Acceptance evidence is CPU state, retained packet memory, callback order, and matching frame hashes; static fixture images are not gameplay proof.
