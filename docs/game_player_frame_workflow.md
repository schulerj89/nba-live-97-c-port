# Original player rendering pass

`game_player_frame.c` owns the visible CPU effects of GAME `52914`, its player-ground-shadow `49E9C -> 55FE4` path, and its off-screen-control-indicator `4C5E8 -> AA468` path. The C++ `GamePlayerFrame` adapter invokes the existing `5200C`, `55368` and `525AC` owners against the same retained body buffers and `GamePlayerProjectionGeometry`. The shadow and indicator reuse the existing `56914` packet linker. Production contains no instruction interpreter, emulator, frontend six-clip decoding or fabricated successful child callback.

This closes the player pass with its required inputs. It does not establish natural match entry, load a camera or body/texture resources, initialize the ordering tables, rasterize the resulting packet chain, or own the remaining calls in `49018` such as ball, net and labels.

## Source order and retained quirks

At entry, `52914` adds `B72D8` to `B72D4` with wrapped 32-bit arithmetic and stores the sum before its signed comparisons. A result at least 16 becomes 15 with increment -2; a result below 2 becomes 2 with increment 2. It then publishes context base `F0ED8` to `F0ED4` and clears index `1029B0`.

Each ordinary iteration:

1. Read the physical entity's extra-angle halfword through `FC654 + index*244 + 98`. Separately read selected entity X/Z/height and yaw through the live `FC650[index]` table. The table pointer and table entry are reloaded for each coordinate; the context pointer captured for these stores stays captured. Coordinate stores use signed shifts by five.
2. Publish the exact root, work, foot and hand reference slots; publish the extra angle shifted by two; store selected yaw at context `+16`. In particular, the first hand endpoints belong to `FAA04` and the second to `FED20`, with eight-byte strides. These are world endpoints from `55368`, not projected vertices.
3. Run actual `5200C -> 55368` with shared retained geometry. Read the now-live projected root through `FEA94[index]`.
4. If signed X lies in [-40,552] and signed Y in [-40,496], run actual `525AC`. Reload mask `1F80000C` through `55F0C` and index. If the bit selected by the low five index bits is clear, run the player shadow.
5. Always run `4C5E8`, including for off-screen roots. Reload index and context, add one and `BCC`, then use the signed index comparison against ten. This is not replaced with a fixed ten-element native loop. A native operation bound refuses rather than repairing corrupted or aliased source counts.

`545C4` and `545E0` switch the original stack to scratch address `1F8003F8`, save the prior SP there and restore it afterward. They are not clocks or timers. As with the existing matrix owners, private ABI stack/register-save effects are excluded from this native entry. The caller must exclude source stack/code aliases; this entry neither invents an original SP nor exposes its saved word. The adapter rejects allocation mappings overlapping scratch `1F800040..1F8003FF`; the actual visible mask at `1F80000C` can be owned separately. Original raw-instruction comparisons give the scratch stack its own backing and exclude only those private ABI writes from visible-memory comparisons.

The shadow repeatedly reads context X/Z while constructing four signed16 corners at `D8EF4`, at ground height zero with half-extent 128. It loads the real `F9FD8` camera, uses RTPT for the first three corners followed by RTPS for the fourth, writes packet XY at offsets 0x08/0x10/0x18/0x20, and links the preinitialized packet at `D8F14 + index*80 + bank*40` into ordering-table offset `3FF8`. It does not cull on projection flags. The helper's FLAG/IR0/SZ3 reads and returned values only feed dead private-stack results in this caller; these do not alter retained geometry and are not fabricated as visible output stores.

The indicator preserves all early and late eligibility checks. In particular, the early selection test accepts any negative halfword, but after writing the copied packet and XY, the late test accepts exactly -1. It can therefore modify a packet without linking it. Its fallback screen position is `(1000 + bank*4,1000)`. Anchor bounds are X30..460/Y30..200, with the original eight-direction lookup. RGB reads reload physical entity, index and bank separately. Width and height are absolute differences of unsigned UV bytes, without adding one. The final link uses the previously captured packet offset even after later live eligibility reads.

`AA468` receives exactly 40 bytes from `FAA54 + direction*40`. Its ordinary aligned path snapshots four source words before each four-word write batch. Backward copying occurs only for signed source < destination < source+40. The final two backward words still perform both original LWL/LWR reads and both SWL/SWR stores, even though each access is a complete aligned word. Signed ADD overflow on the backward-path address additions remains an explicit trap result. This player-local owner remains frozen to its reached 40-byte domain; the separately recovered [complete `AA468` owner](game_memory_copy_workflow.md) covers unaligned and general-length calls with the same source ordering.

## Memory and refusal contract

The C access boundary carries actual numeric source addresses, byte widths and per-byte knowledge. It distinguishes pointer stores from scalar stores, and an opaque fullword copy can preserve an existing normalized reference identity. The access backend validates every reached metadata byte before reporting unknown data, including write-only spans. Unknown unused bytes are not silently zero-filled or marked known. Rotation-word padding and vertex-Z high halves are validated over the original four-byte span but need not be known when discarded by the original geometry register write.

The C++ adapter borrows `Nba97GameBodyBuffer` arrays and one explicit original base-address entry per allocation. Address mappings must be canonical, nonoverlapping and nonwrapping; unknown mappings cannot supply a source address. This mapping validation does not preflight buffer contents. Each actual memory access validates its reached bytes, cells, alignment and knowledge. Normalized pointer reads require their true source encoding. Pointer stores resolve retained allocation identity where possible, including a final one-past context pointer; an unmapped known pointer remains its actual raw value. A later child requiring an unavailable normalized reference explicitly refuses. Partial writes to normalized pointer cells refuse `ADDRESS_REQUIRED`; callers must not silently manufacture their encoded untouched bits. Raw GPU tag/ordering words remain raw cells.

`GamePlayerFrame` provides `run`, `shadow`, `indicator` and the narrowly scoped `copy40`. These methods are synchronous; backing bytes, knowledge, cells and address bindings must outlive the call and must not alias adapter metadata or journals. Copying this C++ adapter alone does not clone its borrowed memory. To publish atomically, clone/rebind the complete retained memory owner and copy geometry before running, then publish only after success.

Refusals retain all earlier source CPU writes and math effects. `Nba97PlayerFrameProgress` reports the outer stopped address/PC, successful calls and source iteration counts. `last_child`, `root_progress`, `part_progress`, `projection_progress` and `last_child_writes` expose the actual child refusal and its ordered stores. Per-call diagnostics reset before entry; geometry and source memory do not reset. The source operation bound and per-child journal bound are host safety limits, not original counters or successful source returns.

This pass does not create substitute textures or claim uninitialized packets are ready. The existing ignored render-frame audit records that loader graph.
- CMake registers the new C and C++ files plus `game_player_frame_tests.cpp`. It links existing player-root/geometry/projection C and C++ owners, court-packet C, court-geometry C++, and existing Zdomf arithmetic dependencies. The application includes the player pass and the separately recovered [live camera](game_camera_workflow.md); this registration does not connect them to natural match entry.

Twelve additional knowledge probes include ten exact refusal prefixes and two inputs whose unknown bytes the source overwrites before consuming them. Camera, entity, bank, control and ordering state in these compositions are explicit fixtures, not observations of cold startup.
